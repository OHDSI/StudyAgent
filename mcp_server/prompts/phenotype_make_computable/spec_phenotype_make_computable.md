Return one cohort-plan JSON object only. Do not emit R or Circe JSON.

Supported deterministic plan modes are `condition_entry`, `visit_overlap`, and `temporal_followup`. Use `mixed_domain_clarification` whenever reviewed concept-set items span multiple OMOP event domains and the caller has not explicitly stated whether those domains are qualifying diagnoses, alternative qualifying events, or supporting evidence only.

For every supported plan, state the entry limit, prior continuous-observation days, exit strategy, and era days. Emit `exit_strategy` exactly as `"observation"`, `"end_of_observation"`, or a fixed object with `type: "fixed"`, optional `index`, and integer `offset_days`. Every proposed concept set must contain policy-bearing `items` with `concept_id`, `domain`, `include_descendants`, `include_mapped`, and `is_excluded`. Use only reviewed candidate concepts and preserve their descendant, mapped, and exclusion policies. Do not invent concept identifiers.

Return one `candidate_assessments` item for every candidate in the supplied `assessment_scope.direct_candidate_ids`, with its `concept_id`, a boolean `precision_eligible`, and a brief clinical rationale. Candidates outside that scope are retained as retrieval context for human review and must not be assessed, proposed, or treated as automatic inclusions. Treat candidates reached through `Ontology-descendant`, `Patient context`, or `Lexical via standard` as review evidence, not automatic inclusions. Mark similarly spelled but anatomically or clinically different direct candidates ineligible. A candidate may be eligible yet omitted from the proposed concept set when its policy needs a human decision. Use candidates marked precision eligible for positive inclusion. A precision-ineligible candidate may appear only as an explicit exclusion from an included-descendants ancestor. If an included-descendants ancestor and its non-excluded descendant are both proposed, identify the hierarchy coverage in the rationale or warnings but retain the explicit child policy for human review; an excluded descendant remains a valid exception policy.

`visit_overlap` requires a Condition index set and Visit set plus explicit `visit_overlap_mode` (`entry` or `attrition`). `temporal_followup` requires named Condition index and trigger sets, follow-up and washout days, and a clear fixed-exit anchor. Do not use free-form temporal windows or unsupported index-day boundary behavior.

Simple direct entry is supported for Condition, Drug (exposure records only), Procedure, Measurement (without value constraints), Observation, Visit, and Device. A single Condition/Observation concept set may use `multi_domain_entry_policy: "any_qualifying_domain"` only when the caller explicitly confirms that either record type may define the earliest index. If a requested feature is outside these modes—such as drug/condition eras, measurement values, arbitrary boolean logic, or another unresolved cross-domain policy—return `needs_clarification` or `not_expressible` and explain the missing decision. Never approximate it.
